## New findings

### I1 — major — line terminators the indexers count but Tree-sitter does not (lone CR; U+2028/U+2029 for TypeScript) shift every later occurrence onto another line: definitions get another method's SCIP key and exact `CALLS` are anchored at other calls
- Repro (real `rb-scip-java:0.13.1`): `src/main/java/t/LoneCr2.java` =
  `package t;\n\npublic class LoneCr2 {\n\tint m1() { return 0; }\r\tint m0() { return 1; }\n\tint m2() { return zeta(); }\n\tint m3() { return beta(); }\n\tint zeta() { return 2; }\n\tint beta() { return 3; }\n}\n` (one lone `\r` on line 4). javac (and scip-java) count the `\r` as a line terminator; Tree-sitter counts rows by `\n` only, and `rb_scip::decode` splits the source on `\n` only (`crates/rb-scip/src/decode.rs:116`).
- Observed in the dump: `Symbol` named `m2` keyed `…t/LoneCr2#m0().`; named `m3` keyed `#m2().`; named `beta` keyed `#zeta().`; the real `m0` and `zeta` keep heuristic keys; `E #m2() CALLS #zeta()` (`scip`, 5) with evidence `[5,19,5,23]`, which is the text `beta` inside `m3`. `rb status` shows nothing unusual (`definitions matched … unmatched 1`, `unconverted 0`). `LoneCr.java` (lone CR inside a method body): `user() CALLS alpha()` evidenced at the `gamma()` call, `user() CALLS gamma()` at the `omega()` call, `user() → omega()` lost.
- Same with scip-typescript (`sourcegraph/scip-typescript@sha256:028c…`): `src/cr.ts` (lone CR) and `src/ls.ts` (`m1() { return "a<U+2028>b"; }`, a legal ES2019 string literal) give `K#m0().`/`L#m2().` keys on the `m2`/`m3` methods, `beta` keyed `#zeta().`, and `L#m2() CALLS L#zeta()` evidenced at `this.beta()`.
- Expected: an occurrence is either mapped to the token the indexer meant or counted as unmatched (invariants 2 and 6). Two defects combine: (a) the decoder converts the indexer's line numbers as if lines were `\n`-separated (javac: `\n`, `\r`, `\r\n`; TypeScript: those plus U+2028/U+2029); (b) an exact-span definition occurrence is accepted without checking that it names the definition (`crates/rb-indexer/src/scip.rs:225`, `at_name(is_global_definition)`), unlike the amendment-7 fallback and the amendment-53 supertype guard, and a reference occurrence is accepted at a span without comparing its symbol's name to the token (`scip.rs:351`).
- Prevalence: 0 lone CRs and 0 U+2028/U+2029 in the four public repositories' Java/TS sources; the defect is reachable from legal source only, like H1 was.
- Fix direction: compute the indexer's line starts by its own terminator rule from the source text and map `(indexer line, column)` → byte offset → Tree-sitter `(row, byte column)`; and guard exact-span definition matches with `last_descriptor_name(symbol) == definition name` (scip-typescript's object-literal properties carry a `0` suffix, `validate0:` — the guard needs the same normalisation the by-name fallback already uses).
- Regression tests: rb-scip decode unit with a lone `\r` and a U+2028 line (scip-java and scip-typescript metadata); join unit with a definition occurrence of `m0` at `m2`'s exact name span → not matched, counted.

### I2 — minor — scip-typescript's local → local relationships are never counted `in project`, contrary to amendment 54
- Repro (t6ts `src/mixin.ts`): `export function inner() { class A { m() {…} } class B extends A { m() {…} } … }`. All four (`A`, `A#m`, `B`, `B#m`) are bound local definitions (definition occurrences `local 6..9` at their names); the index relates `local 8 → local 6` and `local 9 → local 7`. `rb status`: `relationships dropped 2 (0 in project)`.
- Cause: `in_project` for a local looks up the local's `display_name` (`crates/rb-indexer/src/scip.rs:283`) and compares it with Tree-sitter's name; scip-typescript 0.4.0 leaves `display_name` empty for every local (class-validator: 0 of 1,258 local occurrences have one; jsoup 35,175 of 35,278 do). The same emptiness makes amendment 54's by-name fallback for locals dead for TypeScript.
- Expected (amendment 54): "between two locals … the link is dropped and, both ends being bound, counted in project". Count bound locals as in project by binding, not by display name. Regression: join unit with two TypeScript-style locals without display names.

### I3 — minor — a comment inside a qualified supertype name still loses the class's edges
- `class Q1 extends t./* inner */CBase { @Override void go() {} }` (real scip-java index has `t/CBase#` inside the span and both relationships): no `Q1# → CBase#`, no `Q1#go() → CBase#go()`, `1 supertypes unresolved`. Location: `crates/rb-syntax/src/decorations.rs:264` (`supertype` uses the raw node text). Fix: build the name from the identifier children only.
