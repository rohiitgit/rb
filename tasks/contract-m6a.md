# M6a contract: SCIP coverage on Java and TypeScript — Lombok-generated members, TypeScript interface-method `IMPLEMENTS`, npm/Yarn workspace installs, in-repository `file:` packages, the reactor budget, `rb serve`'s sweep order (draft, planner, 2026-10-07)

**Status:** contract written 2026-10-07; not started.

Written before any code. M6a is done only when every assertion below is backed by a passing test or a recorded measurement. "Verified facts" are what was read in the code, the goldens or the records at commit `cfa8ab9` (M5 closed; `PIPELINE` `m5-3`, `RECIPE` `m5-egress-1`), plus two probes the planner ran on 2026-10-07 in its scratchpad against the images already on this machine (P1, P2 below; phase 0 re-runs them and keeps the raw outputs under `var/m6a/phase0/`).

M6a is the first of M6's sub-milestones (design §13: M6a–M6j). It takes the M5 open items that harden what already exists, Java and TypeScript SCIP coverage, before any new language: contract-m5 open items 1, 3, 4, 5, 8, 24 and 25 (amendment 17). It adds no node kind, no edge kind and no new certainty; it changes which scip-java documents are accepted, which `IMPLEMENTS` edges a scip-typescript interface gets, how TypeScript jobs are grouped and exported, the SCIP budget, and `rb serve`'s start-up order.

This contract follows the M5 format and applies, from the start, the lessons M3b–M5 paid for:
- the soundness claims and the closing bar are stated before any review (lesson 2026-10-06, "state the soundness bar before adversarial review starts, and close on verification");
- every rule that admits data is an **allow-list** of positively identified forms, never a list of bad forms (lessons 2026-10-06, "a deny-list … is never complete", "gate what carries the effect");
- a rule that drops data counts what it dropped (lesson 2026-10-01, "a rule that suppresses a fallback must count what it suppressed");
- an indexer's behaviour is measured on its real output before a rule depends on it (lessons 2026-10-01 and 2026-10-06: "an indexer's column convention is measured …", "a check that relies on an indexer's metadata is measured for every indexer and every kind"): P1 and P2 were run before this contract was written;
- a relationship flag carries no direction; direction is confirmed against syntax (lesson 2026-10-01);
- growth is tested by counted operations, never by wall clock (lesson 2026-10-06);
- invariant 1 compares dumps against the previous milestone's close (`cfa8ab9`) with every changed line classified (lesson 2026-09-30, "never attribute a metric change without diffing the edge sets").

## Soundness claims and closing bar (read first)

M6a's outputs whose failure would be silent: an exact edge built from a member only javac's annotation processor sees; a Tree-sitter definition given the key of a generated member; an `IMPLEMENTS` edge in the wrong direction; a TypeScript project indexed with another project's dependencies or with files the job cannot account for; an index reused under a build setting that produced another one; a server that writes although it refuses to start. **Everything not proven takes the safe direction:** a document that is not accounted for whole stays rejected (Tier B, labelled), a member relationship the syntax does not confirm gives no edge, a workspace whose membership cannot be read stays ungrouped (today's jobs), a link target outside the repository makes the job `unsupported`.

**What M6a must not change.** No `--no-scip` dump changes anywhere (Tier B is untouched). SCIP dumps change only through:
- (L) documents accepted after D1's removal: their heuristic edges replaced by exact ones, their coverage counters, `documents_rejected` and its reasons;
- (T) new `IMPLEMENTS` edges from scip-typescript interface methods (and the `relationships_dropped` counts they no longer add to);
- (W) TypeScript projects whose job grouping or export changed (S8–S11): their status lines, their coverage, the edges of files that now have documents;
- (B) nothing from the budget flags (S13 proves it).

This is invariant 1, checked against `cfa8ab9` dumps of every fixture (with and without SCIP) and of the M6a measurement repositories at their pins, every differing row classified as L, T or W by a script that reads the before and after rows and the rejected-document list.

**Closing bar.** Decided now:
1. **Evaluator pass 1 is a full review,** adversarial probing of the claims above included (layouts of Lombok annotations, annotation processors, member names that shadow generated ones, interface chains, workspace manifests, lockfile links). Each finding is fixed test-first as an amendment.
2. **Evaluator pass 2 is verification-only.** It re-runs every pass-1 finding's repro and its controls, the regression suite and the mutations, invariant 1, and the public-repository determinism checks (fresh == cached). It does not re-run timings (S13's numbers are records, not pass/fail).
3. **A pass-2 result blocks closing only if it is one of:**
   - (a) a pass-1 fix that does not hold;
   - (b) a regression;
   - (c) a failure of a claim above through a form its mechanism controls: a false exact edge (wrong source, target or direction) from a document accepted only because of D1's removal, or with a generated occurrence as its source, target or anchor; a Tree-sitter definition keyed by a generated member; an interface-method `IMPLEMENTS` whose source does not override its target or that runs from super to sub; a workspace member admitted through a glob form outside D5's allow-list; an exported file outside the job root that is not a link target inside the repository, or a cache key that does not change when an exported file changes; an index reused across thread settings; a write by a `rb serve` that refused its bind;
   - (d) a non-deterministic dump;
   - (e) a failed test, guard or verification step.
4. **Not blocking:** a new form in a residue class above (recorded as an open item for the sub-milestone that owns it, with its example); a precision miss that contradicts no stated rule (a generated member's callers missing, a workspace that still cannot fetch for a recorded registry reason); §12.5's SCIP full-index target missed again with its profile recorded.
5. **Timings are measured, not asserted** (S13): hardware, Docker VM allocation, load averages at start and end, and run counts stated with each number.

## Engineer declaration

**Canonical state:**
- **No migration, no table change.**
- **Graph:** no new node or edge kind. `rb_indexer::PIPELINE` becomes `m6a-1` at the first dump change (phase 2, D1) and is bumped on each later dump change (`m6a-2` with D4, `m6a-3` with the workspace grouping).
- **Recipes (D8):** `rb_scip::RECIPE` is split per indexer. scip-java's recipe string stays `m5-egress-1` byte for byte (so every cached Java index stays valid: the Java commands do not change at the default budget), extended to `m5-egress-1+T<n>` only when `--scip-maven-threads n` > 1. scip-typescript's becomes `m6a-ts-1` at phase 6 (root fetch for workspaces, repository-shaped export), which invalidates every cached TypeScript index once.
- **Configuration:** new `rb index` flags `--scip-cpus` (default 2, 0.5–64), `--scip-memory` (default `4g`, `<n>m` or `<n>g`, 512m–64g), `--scip-maven-threads` (default 1, 1–16), with env `RB_SCIP_CPUS`, `RB_SCIP_MEMORY`, `RB_SCIP_MAVEN_THREADS`. Nothing in `rb.toml`.

**Derived** (never stored separately):
- per document: the set of marker spans and the removed occurrences (D1);
- per project coverage (stored in the `scip_status` diagnostic like the existing counters, written only when non-zero, D3): `lombok_removed` (occurrences removed), `documents_lombok` (accepted documents with at least one removal), `workspace_members` (members grouped into the job), `documents_outside_root` (index documents ignored because they lie outside the job's root), `link_targets` (exported link-target directories);
- the job list (D5) from the file list and the root manifests.

**Invariants:**
1. **Dumps.** `--no-scip` dumps byte-identical to `cfa8ab9` on every fixture and measurement repository. SCIP dumps differ only in rows classified L, T or W (soundness section), every row classified by script.
2. **Agreement checks unchanged.** `definition_disagreement`, `definitions_unpaired` and `structure_disagreement` keep their code; D1 only changes their input (a document's occurrences minus the removed ones). A document with no `lombok/Generated#` occurrence is judged exactly as at `cfa8ab9` (unit: same verdicts and same joined output on every fixture document and on a corpus of synthetic indexes).
3. **Removal is positive and counted.** Only occurrences on, or (definitions) enclosed exactly by, a marker span are removed; every removal is counted; a document whose verdict changes is counted in `documents_lombok`.
4. **Direction.** Every `IMPLEMENTS` edge has an `is_implementation` relationship from its source's own symbol information and a declared-clause walk from the source's type holder to the target's type; scip-java origins also need amendment 78's confirmation.
5. **Membership is an allow-list.** A package joins a workspace job only through D5's forms; anything else leaves the workspace ungrouped, counted by reason.
6. **Exports.** A job's export is exactly its root's tracked files plus in-repository link targets' tracked files (no `node_modules`, no host path); the cache key hashes every exported `(path, blob)`; a link target outside the repository makes the job `unsupported` before anything is written.
7. **Cache identity.** At default settings every scip-java job's input hash equals `cfa8ab9`'s for the same files; a thread count above 1 always changes it; every scip-typescript job's hash changes once (recipe `m6a-ts-1`).
8. **Determinism.** Fresh == cached, two repository names, forced rebuilds: byte-identical dumps on the fixtures and the measurement repositories; S13's thread settings give byte-identical dumps.
9. **Bounded work.** Marker lookup per document is one pass over its occurrences into a sorted set; the glob matcher has no backtracking beyond one `**` per pattern; link resolution is lexical with a visited set (no symlink following; a link target that is itself linked is resolved once).
10. **Stated complexity is tested by counted operations** (≤ 5× the operations for 4× the input): D1's removal, D5's membership, D7's export selection (S19).
11. **`rb serve` writes only after its bind check** (S14).

## Decisions (made here, with reasons)

- **D1: Lombok-generated occurrences are identified by Lombok's own marker.** P2 (scip-java 0.13.1, Lombok 1.18.34, JDK 21) shows:
  - every member Lombok generates (`@Data`'s setters, `equals`, `hashCode`, `canEqual`, `toString`; `@NoArgsConstructor`/`@AllArgsConstructor`'s constructors; `@Builder`'s nested `MoneyBuilder#` with its constructor and methods and `builder()`; `@With`'s `withX`; getters from a class-level `@Getter`/`@Value`/`@Data` and from a field-level `@Getter`) has a definition occurrence whose **enclosing range** is either the class annotation's span (`@Data` at line 14 columns 0–5, the `@` included) or a span from the field's name to the end of its declarator (`name` at 18:19–24 for `private String name;`), and Lombok's `@lombok.Generated` annotation of that member is a reference occurrence of `lombok/Generated#` at **exactly that span**;
  - the generated bodies' references (`p/User#getName().`, `java/lang/Object#equals().`, the fields, the parameters) are occurrences **at those same marker spans**, and the generated methods' parameters are local definitions whose enclosing range is the marker span;
  - the generated definition occurrence's **own** range is not a source position: class-annotation members get a multi-line range starting after the annotation (`[14:5–15:6]`), and field-derived accessors get the first later text match of their name (amendment 7's rule), which can be a call site in another method (`p/User#getName().` defined at `20:43–50`, the `getName()` call inside `greet()`, beside the real reference occurrence there). These are what `definition_disagreement` (a definition on a reference token, inside a method) and `definitions_unpaired` (a method only javac sees) reject today, which explains shardingsphere's 3,771 + 118 rejections by hypothesis (phase 0 and S16 verify).

  **Rule:** in a scip-java document, let `M` be the spans of its reference occurrences whose symbol is `lombok/Generated#` in package `maven/org.projectlombok/lombok` (any version; matched on the parsed symbol's package name and descriptor, not on text). Remove every occurrence whose span is in `M`, and every definition occurrence (global or local) whose enclosing range is in `M`. Then run every existing check and the join on the remaining occurrences, unchanged.

  **Why no real occurrence is removed:** javac gives a real method, constructor or type an enclosing range from its first modifier or annotation to its closing brace, and a real local (a parameter, a lambda's, an anonymous class's) the range of its own declaration; none equals a lone annotation's span or a name-to-declarator-end span (P2's real members: `greet()` `[20:4–66]`, `helper()` `[21:4–44]`). A real reference occurrence names a token (amendment 59), and no token starts with `@` or ends after a declarator's terminator. A user-written `@lombok.Generated` on a hand-written method is a reference at the annotation's span; the method's own enclosing range starts there but ends at its closing brace, so it is not removed (S1 row (f)). **Why the rule cannot make a bad document pass:** the checks still see every remaining occurrence; the only facts withheld from them are positively marked generated code, which has no source text for Tree-sitter to disagree with. **Cost accepted:** generated members are not nodes (F5); references to them count as `unanchored`.
- **D2: the removal runs before every document check and before the join, in `rb_indexer::scip::join`, for scip-java documents only.** The decoder (`rb-scip`) is unchanged; a document's `rejected` reasons from the decoder (input rejections: encoding, escapes, terminators) are applied first and are never cleared by D1. scip-typescript documents never carry the marker and are not examined.
- **D3: counters appear only when non-zero.** `scip_status` coverage JSON gains `lombok_removed`, `documents_lombok`, `workspace_members`, `documents_outside_root`, `link_targets`, each serialised only when non-zero, and `rb status` prints `, lombok-generated <n> in <d> documents`, `, workspace <k> members`, `, <n> documents outside the root`, `, <n> link targets` only when non-zero. So no fixture's dump or status golden changes through the counters alone (the fixtures at `cfa8ab9` have none).
- **D4: the walk from a scip-typescript interface steps without origin confirmation.** P1 (scip-typescript 0.4.0, digest `sha256:028c0042…`): for `interface Mid extends Base { m(): void; extra(): void }`, `Mid#m()` relates `is_implementation` (and `is_reference`) to `Base#m()`; `Other#n()` (in `interface Other extends Mid, Base`) to `Base#n()`; `Base#m()` relates to nothing; the types `Base#`, `Mid#`, `Other#` relate to nothing; a class relates its type to every supertype and its methods to every overridden method (`Svc#m()` → `Mid#m()`, `Base#m()`). Amendment 78's walk needs the origin's type relationships, so every interface-method relationship is dropped today (`relationships_dropped`). **Rule:** when the holder of the relationship's source is a scip-typescript interface (Tree-sitter kind `Interface` in a TypeScript/JavaScript document of a scip-typescript project), the walk steps onto each declared supertype resolved through the index's own type occurrence (amendment 26, accepted only when the occurrence names the written type), without the `related` set; everything else is as today (depth cap 64, visited set, the target reached only through declared clauses). **Gate (phase 0):** P1 extended to these forms, each with its raw relationships recorded: a chain of depth 3; generic interfaces (`Repo<T> extends Base`); a supertype imported from another file and from another workspace package; a namespace-qualified supertype (`extends ns.Base`); declaration merging (two `interface Mid` blocks); overload signatures; optional methods; an interface extending a class; a property signature overriding a method signature; call and construct signatures. If any super→sub member relationship appears, D4 is not built and fork F3 goes back to the orchestrator.
- **D5: workspace membership.**
  - A **workspace root** is a package root (a directory with `package.json`) whose `package.json` parses as JSON and has `workspaces` as an array of strings or as an object whose `packages` is an array of strings, **and** which holds `package-lock.json` or `yarn.lock` (a `yarn.lock` whose first non-comment line starts `__metadata:` is Yarn ≥ 2 and is not grouped: reason `yarn_berry`).
  - **Allowed glob forms** (each pattern relative to the root, `/`-separated): literal segments of `[A-Za-z0-9._@+-]` (not `.` or `..`); `*` as a whole segment (one directory); `**` as a whole final segment (any depth, at least one). A trailing `/` is ignored. **Any other pattern** (a leading `!`, `{`, `[`, `?`, a partial `*` such as `pkg-*`, `..`, an absolute path, an empty string) makes the root **ungrouped**, counted with reason `workspace_glob_unsupported`. *(Note for the generator: npm's `pkg-*` form is common; it is left out deliberately, since the allow-list starts narrow; phase 0 counts the forms on the measurement repositories and records whether widening is needed, by amendment.)*
  - A **member** is a package root strictly under a workspace root whose path relative to the root matches an allowed pattern. Members' own lockfiles are ignored (npm and Yarn use the root's). A workspace root under another workspace root is a member of the outer one only if matched; otherwise it is its own root (npm does not nest workspaces).
  - The **job** of a workspace root indexes every `tsconfig.json` directory whose nearest package root is the root or one of its members (D6); a non-member package root under the root keeps its own job as today.
  - A workspace root **without** a lockfile is not grouped (reason `workspace_without_lockfile`): `npm install` would resolve every member's ranges afresh, and grouping would let one member's unresolvable range fail its siblings. This keeps `polyglot-monorepo` (root `workspaces` with no lockfile, verified fact 11) exactly as at `cfa8ab9`.
- **D6: workspace fetch and index.** The fetch phase runs at the workspace root with today's commands (`npm ci` with `--ignore-scripts` and the quiet flags; `yarn install --frozen-lockfile --non-interactive --ignore-scripts`), which install every member and link siblings. The index phase passes the job's `tsconfig.json` directories, sorted, after `--` (as today); scip-typescript's `--yarn-workspaces` is not used, because the explicit list is the one D5 decided. The job is `unpinned` exactly when today's rule says so (no lockfile; never for a grouped root).
- **D7: repository-shaped exports for scip-typescript jobs; link targets.**
  - The export writes each file at its **repository path** under the job's work directory, which is mounted at `/src`, and the container's working directory becomes `/src/<root>` (today: the root's files at the work directory's top, working directory `/src`). scip-typescript's document paths are relative to its working directory, so they are unchanged; phase 0 checks it (`ts-express-prisma` and `polyglot-monorepo` SCIP dumps byte-identical under a scratch build of the layout change alone).
  - **Link targets:** for a job whose root holds `package-lock.json` (lockfile v2/v3), every entry of `packages` with `"link": true` whose `resolved` is a relative path, and every `packages` key that starts with `../`, is resolved lexically against the root (`.` and `..` folded; no symlink is followed). A target inside the repository and outside the root adds its tracked files, minus any `node_modules` path, to the export (with its own `package.json`); a target outside the repository makes the job `unsupported` (reason `link target outside the repository`, no host path). Version 1 lockfiles and `yarn.lock` are not read for links (M6e).
  - **Cache key:** `project_input_hash` covers the root's files and every exported link-target file (today it filters to the root, verified fact 9).
  - **Documents outside the root:** a document whose path, joined to the root and folded, leaves the root (a link target's sources that scip-typescript also indexed through the link) is ignored and counted in `documents_outside_root`; the link target's own job, if it has one, owns its files (`owner_root` unchanged).
- **D8: per-indexer recipes.** `RECIPE` becomes `RECIPE_JAVA` (`m5-egress-1`, unchanged) and `RECIPE_TS` (`m6a-ts-1`); `project_input_hash` takes the job's recipe. A unit pins the Java hash of a fixed input to the value `cfa8ab9`'s code computes, so the split cannot silently invalidate cached Java indexes (lesson 2026-10-01, "output that passes through a shared cache …").
- **D9: budget flags (open item 1).** `--scip-cpus`, `--scip-memory`, `--scip-maven-threads` (bounds above), host-side only (lesson 2026-10-07, "an allow-list the adversary can extend is no allow-list" applies to resources too: the indexed repository must not raise its own budget). `-T <n>` is appended to both Maven phases' arguments only when n > 1, and the Java recipe string gains `+T<n>` then. The fetch and index timeouts keep `--scip-timeout-secs`.
