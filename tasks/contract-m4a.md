# M4a contract: endpoints, HTTP clients, stitching and `rb path` (draft, planner, 2026-10-06)

Written before any code. M4a is done only when every assertion below is backed by a passing test or a recorded measurement. Nothing here is built yet; "verified facts" are only what was read in the code or the design at commit `38d55e4`.

## Scope

M4 in the roadmap (design §13) is split like M2 and M3:
- **M4a (this contract): endpoints and request paths.** Route packs (§4.5), HTTP-client packs (§4.5), endpoint normalisation (§10.1), `http_stitch` (§10.2), `rb path` (§10.3, §11.1), the Service Card's API section (§9.5), the endpoint roll-up of `rb impact` (§9.3, deferred by M3a), Q4 goldens on `polyglot-monorepo` (§9.6), and precision guards (must-exist and must-not-exist edge lists, §12.1).
- **M4b (later contract): DI and dispatch.** Spring DI synthesis (§6.4: `Bean`, `InjectionPoint`, `INJECTS`, `@Qualifier`/`@Primary`/`@Profile`/conditional), Spring Data synthetic repository implementations (§6.4 step 5), the RTA filter (`impl_instantiated`, `precision=rta` as the default for Q1/Q4, §6.2), derived `DEPENDS_ON` service edges (`via=calls|http|package`, lockfile versions, §5.5, §9.5), the rest of the full Service Card (Dependencies, Depended on by, shared tables, call-graph summary), Q3's service roll-up with endpoints and the `CONSUMES` distinction (§9.4 steps 3–5) and its goldens, orphan detection (carried from M3b scope), and entry-point marking in `rb callers` (§9.2).
- **Deferred beyond M4 (M5/M6), with the reason:**
  - **Python routes and clients** (Flask, FastAPI, Django, `requests`, `httpx`): no fixture has a Python service, and Q4 on `polyglot-monorepo` already spans TypeScript, Java and Go. The normaliser accepts Flask's `<int:id>` syntax anyway, since it is a pure function. M6 (breadth). `rb-syntax` facts stay language-neutral, so Python extraction comes for free (S1 smoke test only).
  - **NestJS, Fastify, Koa, chi, Spring `@HttpExchange` interfaces, `got`, superagent, Angular `HttpClient`**: M6 packs. Each is a pack plus fixtures (§4.5), with no core change.
  - **Gateway rewrites** (nginx `location`/`proxy_pass`, k8s Ingress, Spring Cloud Gateway): §10.1 and §13 already place them in v1.x/M6. In M4a a host that names a service exposing no endpoints is treated as a proxy (S13).
  - **YAML and other config** (`application.yml`, profile files `application-<p>.*`, docker-compose, k8s manifests, `.env`): no YAML parser is a dependency today (verified: `Cargo.toml` workspace dependencies), and adding one is not needed for the exit criteria. M4a reads `src/main/resources/application.properties` only (S4, S12). A Spring YAML file that mentions `context-path` gives `spring_config_unread`, so the gap is counted, not silent (lesson 2026-10-01, "a rule that suppresses a fallback must count what it suppressed").
  - **External `Endpoint` nodes** (§10.2 step 4, `external=true`) and **generated-client matching by operation ID** (§10.2 step 5, OpenAPI/gRPC): unmatched and external calls become counted diagnostics with their host (S14); nodes for them come with the `openapi`/`grpc` packs (M6).
  - **Mermaid and DOT output** for `rb path` (§10.3): text and JSON only (S18).
  - **External package allow-list sinks** in `rb path` (§10.3 step 2): there are no external `Symbol` stubs (contract M3b amendment 11), so there is nothing to allow-list yet.
  - **REST API** (`GET /v1/repos/{repo}/paths`, §11.2): M5.

## Engineer declaration

**Canonical state** (cached extractor output in `FileFacts`, per blob; no new table, no migration):
- **`Decoration.span`**: the decorator's or annotation's own span, so route evidence points at `@PostMapping("/login")` rather than at the method name.
- **Call chains** (`FileFacts.chains`, new): for every outermost call expression, its receiver root as written (`app`, `this.restTemplate`, `axios`, `http`, or none for `fetch(…)`) and its links in order (`route('/x')`, `get(h)`), each link with its name, span and argument summaries. An argument summary is one of: a **string template** (literal parts and holes; each hole keeps its expression text, capped at 256 bytes, and span), a **name** (identifier or member path as written, with span), an **inline function** (its span), an **object literal** (keyed summaries, one level deep), or **other** (no text). Framework-neutral: nothing in `rb-syntax` knows Express or axios.
- **Binding initialisers** (`Binding.init`, new): the initialiser of a declaration as a string template, a call chain, a name, or a fallback `a ?? 'lit'` / `a || 'lit'` (primary name plus default template); plus `Binding.constant` (TS/JS `const`, Java `final`, Go `const`). Recorded for the declarations M3a already records as bindings.
- **Binding decorations** (`Binding.decorations`, new): annotations on Java fields and parameters (`@Value("${k:d}")`), with spans.
- The extractor fingerprint (`rb_syntax::extractor_id`) must cover every new source file, so cached facts from an older extractor are never served.

**Derived** (in `rb-frameworks` as pure functions of facts, and in the indexer per snapshot):
- **Route facts** per file (`rb-frameworks`): method, raw path, framework, handler reference (the decorated definition, an inline function span, or a name to resolve), prefix references (class-level mapping, router mount, group). **Client facts** per file: method (or unknown), URL template, base reference, client kind, source site.
- **Endpoints** (`rb-indexer`, new module): route facts composed with prefixes across files, normalised, aggregated per key, then `Endpoint` nodes with `EXPOSES` and `HANDLED_BY`.
- **Constant folding** of URL holes: same-file constants, imported constants, env references with literal defaults, Spring properties.
- **Stitching**: `CONSUMES` edges with provenance `http_stitch`.
- **Diagnostics and coverage**: one bucket per client call site (S14), route diagnostics.
- **Query-time only** (never stored): `rb path` trees, the Service Card's API, "calls APIs of" and "APIs called by" sections, the `rb impact` endpoint roll-up, the `rb status` `http:` line.

**Invariants:**
1. **Endpoint identity.** An `Endpoint` key is `HTTP <METHOD> <normalised path> @<service key>` (design §8.2 plus the exposing service, decision D1). There is one node per (service, method, path), and exactly one `EXPOSES` edge into each, from that service. Node attributes are a function of all route facts for the key, which are aggregated before the node is added (`GraphBuilder::add_node` rejects a second, different value; verified, `rb-model/src/graph.rs:177`).
2. **Normalisation is one pure, total, idempotent function** used for server routes and client URLs alike: `norm(norm(x)) == norm(x)` (design §12.3). It never fails: input it cannot read becomes a counted diagnostic upstream, never a guessed path.
3. **A stitched edge is never `exact`.** Every `CONSUMES` edge has provenance `http_stitch` and certainty `synthetic`, `heuristic` or `ambiguous` (decision D2). Several candidates give one `ambiguous` edge to each, with `candidates = n`. Zero candidates, more than 16, or an unreadable URL give a diagnostic and no edge.
4. **Certainty is never guessed upward.** An edge's certainty is the minimum over the facts it combines: path composition, handler resolution, base resolution, host resolution and match kind (tables in S7 and S13). Several sites for one `(src, kind, dst, provenance)` edge merge into one edge whose certainty is the best site's and whose attributes come from that site, plus `sites = n`. This is the M3a rule (contract M3a amendment 1), restated because `GraphBuilder::add_edge` rejects differing certainty or attributes for one edge (verified, `rb-model/src/graph.rs:186–199`).
5. **Cross-service only.** A client's own service never supplies candidates. Calls whose only candidates were in their own service are counted (`self`), not linked.
6. **Syntax, not text.** Routes and clients come only from syntax facts: a commented-out route, a path in a doc, or a URL in a string that is not a client argument gives nothing. A framework is recognised through import facts or a qualified name, never by a bare short name alone (lesson 2026-09-29). Mapping annotations on a `@FeignClient` interface (or any interface) are never server routes.
7. **No guessed hosts.** An absolute URL with a literal host that names no service is external: it is counted with its host and never path-matched. A host is matched to a service by one stated rule (S13), and only when that match is unique.
8. **Inline handlers stay scoped.** A route whose handler is an inline function has `HANDLED_BY` to the innermost kept definition containing it, or the `File` for top-level code (the M3a attribution rule), with `handler_spans`. Downstream walks from it follow only those outbound edges with evidence inside one of those spans.
9. **Determinism.** The same commit and tools give byte-identical dumps: fresh vs warm facts cache, two repos, a forced rebuild, and SCIP fresh vs cached. Every output list (endpoints, candidates, tree children, card rows, diagnostics) has a total order: distance, then certainty rank, then natural key (§3.3).
10. **Termination by construction.** Router-mount and group composition, constant folding, upstream and downstream walks, and hop recursion each use a visited set and a stated cap. Every recursion edge, indirect ones included (mount → import → mount; constant → import → constant; endpoint → handler → client → endpoint), has a cycle test and a depth test (lessons 2026-09-30).
11. **Stated complexity is tested.** The stitcher, the composition and `rb path` each have a growth-ratio test (doubling the input at most 2.5× the time) and a pathological wide input with a time bound (lesson 2026-09-30, "complexity claims need a timing test").
12. **Evidence.** Every `EXPOSES`, `HANDLED_BY` and `CONSUMES` edge has at least one evidence row at a real `File`: the route declaration's span (decorator or registration call) for the first two, the client call's span for `CONSUMES` (for Feign, the interface method's mapping annotation).
13. **The M3b tier rules are unchanged.** M4a adds edge kinds; it never adds or removes a `CALLS`, `REFERENCES` or `IMPLEMENTS` edge, and it never changes a symbol key.

## Decisions (made here, with reasons)

- **D1 — Endpoint keys include the exposing service.** Design §8.2's `HTTP <METHOD> <path>` would merge every service's `GET /health` into one node, with one `HANDLED_BY` per service, so neither `rb path` nor stitching could tell them apart. The suffix ` @<service key>` keeps the design's prefix (search by `POST /api/v1/login` still works), and the normaliser percent-encodes spaces, so ` @` cannot occur inside a path. The node's `name` is `POST /api/v1/login`. Design §8.2 is annotated.
- **D2 — `CONSUMES` tops out at `synthetic`.** Design §10.2 called a host-confirmed literal match `exact`. A string match across a network boundary depends on deployment (env overrides, gateways, profiles), which static analysis never sees. `exact` is reserved for facts a compiler would confirm. The string-level match kind is kept separately as `match = exact | suffix`. Design §10.2 is annotated.
- **D3 — Frameworks: Spring MVC, Express and Go (gin plus `net/http`).**
  - **Spring and Express** are what the three fixtures contain. Verified: `@RequestMapping("/api/v1")` with `@PostMapping("/login")` in `fixtures/java-spring-jpa/.../AuthController.java` and `fixtures/polyglot-monorepo/services/auth/.../AuthController.java`; `authRouter.post("/login", …)` mounted by `app.use("/api/v1", authRouter)` across two files in `fixtures/ts-express-prisma/src/{routes/auth,app}.ts`; `app.post("/internal/mfa/email", …)` in `polyglot-monorepo/services/notification/src/server.ts`.
  - **Go over Flask:** the polyglot fixture already has Go services (`services/billing`, `services/billing/cmd/billing`). gin and `net/http` reuse the call-chain facts that Express needs anyway. Flask/FastAPI would need a new Python service and a new client pack (`requests`).
- **D4 — Clients:** `fetch` and axios (TS/JS); Feign, `RestTemplate`, and `WebClient`/`RestClient` (Java); `net/http` (Go).
  - The fixture uses axios (`apps/web/src/api/auth.ts`) and Feign (`services/auth/.../MfaClient.java`).
  - `fetch` is the platform default.
  - `RestTemplate` and `WebClient` are the common Spring clients, and the Spring measurement repository uses them.
  - Go's `net/http` is the standard library.
- **D5 — Config sources:** literals and constants in code, env references with a literal default in code, and `src/main/resources/application.properties` of the Maven service that owns the file. That covers `server.servlet.context-path`, `@Value` keys and Feign `${…}` placeholders.
  - Values from `application.properties` count as **stated config** and may reach `synthetic`. A committed `application.properties` is the deployed default.
  - Env defaults cap at `heuristic`. An env fallback is usually the development value.
  - Everything else is "unresolved", with the bucket counted.
- **D6 — Host → service rule.** A URL's host (lower-cased, port dropped) matches a `Service` when it equals the service's `name` or the last segment of its key, and exactly one service matches. Example: `notification` names `services/notification`, whose `package.json` name is `notification`; verified in the `services.txt` golden.
  - A matched service that exposes no endpoint is a **proxy** (`gateway` → `edge-gateway`, which is nginx). The call is then path-matched across all services and keeps `via_host`.
  - A loopback host (`localhost`, `127.0.0.1`, `0.0.0.0`, `[::1]`) means the caller's own host. It restricts candidates to the caller's own service, so the site always lands in bucket `self` and is never linked (invariant 5). Path-matching it across services would link `selfcheck.ts` to billing's same-path decoy.
  - A literal host matching no service is external (invariant 7).
  - Explicit `rb.toml` host mappings are not built in M4a.
  - This rule is a convention, so it is fork F1.
- **D7 — Inline handlers:** see invariant 8. The alternative was to make each inline handler a node, but locals are not symbols (design §8.2, §4.4). Span-scoping reuses the evidence every edge already carries.
- **D8 — `rb path` walks** cover the handler's service plus library services (`role = library`), since shared code runs in-process. A `CALLS` edge into another deployable service's code is shown as "crosses into `<service>` (not followed)". Only `CONSUMES` counts as a service hop.
  - **Sinks** are `QUERIES → Table` and `CONSUMES → Endpoint`.
  - Nodes whose subtree reaches no sink collapse into "+ k helper calls"; `--full` shows them. This decides the design's open "a leaf is a sink", which would have made collapsing a no-op.
  - Dispatch is CHA (as in `rb callers`), with steps marked `dispatch`. RTA arrives with M4b.
- **D9 — Matching specificity:**
  - An endpoint parameter `{}` matches any client segment.
  - A client hole `{}` matches only an endpoint parameter.
  - A wildcard `{*}` (last segment only) matches zero or more trailing segments and caps the match at `heuristic`.
  - Among path matches, the candidates with the most literal segments win, then an exact method over `ANY`. Ties are ambiguous. This is what Spring, Express and Go's `ServeMux` do at runtime (most specific first).
- **D10 — Precision guards live beside the goldens**, not in the fixtures: `crates/rb-cli/tests/golden/<fixture>/must-exist.txt` and `must-not-exist.txt`, one edge pattern per line. Design §12.1's `expected.yaml` would add a file to each fixture (changing every dump and file count) and would need a YAML parser.
- **D11 — Facts stay neutral.** Call chains and initialisers are recorded for every call and declaration. No framework list lives in `rb-syntax`, so a new pack needs no extractor change. The cost is cache size, which S27 measures.
- **D12 — Spring controllers need a stereotype.** A class contributes routes only when it is annotated `@RestController` or `@Controller` (Spring Framework 6 detects handlers by stereotype, not by type-level `@RequestMapping` alone; recalled, to be confirmed in the reference docs by the generator before coding S4). Mappings declared on an interface that a controller implements (the OpenAPI-generator style) are counted as `route_on_interface`, not resolved, in M4a.

## Amendments (generator, phases 1–4, 2026-10-06)

1. **Phase 1 facts, as built (S1, S2).** Three refinements the assertions did not spell out, each needed by a later step:
   - **Bindings for two more declaration forms.** S2 said initialisers are "recorded for the declarations M3a already records as bindings", but M3a recorded neither Go `const` specs nor Java interface fields (`constant_declaration`), and S12 folds both (`pkg.Const`, `Type.CONST`). Both are now bindings (`constant = true`; interface fields are members). They are also visible to the M3a resolver, where a constant name shadows like any variable; the full e2e suite (15 tests, with containers) passed with no golden change, so no fixture edge moved. Go's `const a, b = …` lists its commas under the `name` field, so names are filtered to identifiers.
   - **Every argument summary carries its span** (`Arg::Other { span }` too), so a pack can find the chain recorded for a call argument at the same span (the `asyncHandler(fn)` unwrap of S5, `http.Post(fmt.Sprintf(…))` of S11). `Init::Call` holds the index of that chain in `FileFacts.chains`.
   - **`DecorationArg.items`**: the elements of an array value (`@GetMapping({"/a", "/b"})`, `method = {RequestMethod.GET, …}`), each decoded like a value, for S4's "arrays give one endpoint per path".
   - String templates decode their literal pieces one by one between holes (an escape never spans an interpolation); the SQL candidates are rendered from the same parts, and every SQL golden is unchanged.
2. **Phase 2 route packs, as built (S3–S6).**
   - **`route_path_dynamic`** (new route diagnostic): a route path or Spring mapping that is not a static string (`@GetMapping(Paths.BASE)`, a template with holes) gives this diagnostic with the text and no endpoint, by invariant 2 (unreadable input is counted, never guessed). Route paths are not constant-folded in M4a; S27 measures whether that costs endpoints on the public repositories.
   - **`ServeMux` subtrees.** A Go pattern ending in `/` (without `{$}`) matches its whole subtree (Go docs, phase-0 facts), so the pack appends `{*}`: `/static/` is `ANY /static/{*}`, `/` is `ANY /{*}`. Without it, `/static/` would normalise to `/static` and never match `/static/app.js`.
   - **Express detection** also accepts a top-level `const express = require("express")` (a syntax fact as specific as an import). Routes registered on a function parameter (`function routes(app) { app.get(…) }`) are not recognised: nothing marks the parameter as an Express app.
   - **gin groups** compose through bindings in effect at the call (M3a extents). Go's extents make a cycle through bindings impossible in real source, so `gin_group_cycles_and_depth_terminate` builds it by widening two bindings' extents; the walk is guarded by a visited set on binding spans and the cap `MAX_GROUP_DEPTH = 32` (a 5,000-deep group chain gives `prefix_unknown`). A parameter typed `*gin.Engine` is a root (prefix `""`); `*gin.RouterGroup`, `gin.IRouter` and `gin.IRoutes` parameters give `prefix_unknown`.
   - **Normaliser details:** braces protect `/`, `?` and `#` only when every brace in the path is closed (so `norm` stays idempotent on unbalanced input); Express's `:id?` optional marker is not a query; `:name*`/`:name+` are catch-alls; a parameter embedded in a segment (`file.:ext`, `{name}.json`) is `{}` flagged `partial`.
