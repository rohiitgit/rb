# M3b contract: SCIP orchestration and exact edges (draft, planner, 2026-10-01)

Written before any code. M3b is done only when every assertion below is backed by a passing test or a recorded measurement. Sections marked *pending research* are filled in once the indexer facts are verified (image digests, invocations, build requirements).

## Scope

Design §5.2, §5.3 and §13 (M3b): run SCIP indexers in pinned containers, join their occurrences with Tree-sitter facts, and replace a project's heuristic edges and symbol keys with exact ones.

- **In:** scip-java (Maven and Gradle) and scip-typescript (npm, yarn and pnpm workspaces) first; the `rb-scip` crate (orchestration, index cache, decoding, join); per-project key replacement; `scip_status` per project; `rb status` coverage of exact vs heuristic edges; Q1/Q2 goldens on the fixtures that build.
- **Out (later):** scip-python, scip-go and the others (M6); change sets and the incremental re-index of only changed projects (deferred again: every project re-indexes when its input hash changes, which is already incremental at the project level); orphan detection (needs exact edges on every project of a service; M4 with routes).

## Engineer declaration

**Canonical state:**
- `index.scip` per project, content-addressed under `(project_input_hash, indexer_digest)` in `rb.scip_index` (bytes, plus `scip_status` and a stderr tail). `project_input_hash` hashes the project's file blob SHAs and its lockfiles, so an unchanged project is never re-indexed.
- The relational tables remain the source of truth for the graph.

**Derived:**
- Symbol keys: for a project with `scip_status = ok`, the SCIP symbol string replaces the heuristic key of every definition the join matches. Definitions the join does not match keep heuristic keys.
- `CALLS`, `REFERENCES`, `IMPLEMENTS` with provenance `scip` and certainty `exact` from occurrences (§5.3). Files of a SCIP-ok project get no heuristic code edges at all.
- `Package` nodes and `DEPENDS_ON` from external symbols (§5.5): manager, package name, version.

**Invariants:**
1. A file the `ok` index of its owning project has a document for is fully SCIP (keys and edges replaced); every other file (under a `failed`, `skipped` or `unsupported` root, or under an `ok` root whose index has no document for it) is fully heuristic; never a mix within one file (revised by amendment 15; the first wording made the unit the project, which cost undocumented files every edge).
2. Every `scip` edge is `exact`; every heuristic edge stays `heuristic`/`ambiguous`. Provenance and certainty are never guessed upward.
3. Containers run with the network disabled during the index phase and never receive credentials or host toolchains; the fetch phase reaches package registries only.
4. One failing project never fails the run: it records `scip_status = failed` with a stderr tail and falls back to Tier B.
5. Determinism: the same repo, indexer digest and cache give byte-identical dumps; a cached index gives the same graph as a fresh one.
6. The join never invents ranges: an occurrence matches a capture only when its range equals the capture's range or its name node (§5.3); unmatched occurrences become diagnostics, counted in coverage.

## Verified facts (checked against primary sources on 2026-10-01)

**`scip` crate 0.10.0** (Apache-2.0, published 2026-09-03), which pins `protobuf = "=3.7.2"`; a consumer must depend on the same pin to name the `protobuf::Message` trait (`Index::parse_from_bytes`). No streaming reader exists in the Rust bindings: an index is decoded whole.
- Ranges: `typed_range` (`SingleLineRange`/`MultiLineRange`, added in 0.9.0) takes precedence over the deprecated `range` (3 or 4 ints); half-open, 0-based. **scip-java ≥ 0.13 emits typed ranges only; scip-typescript emits the deprecated form only**, so the decoder handles both.
- Position encoding: both indexers leave `Document.position_encoding` unset. The proto's guidance for JVM and TypeScript indexers is UTF-16 code units, and both compute columns that way (javac `LineMap` columns, `ts.SourceFile.getLineAndCharacterOfPosition`). The decoder converts to byte columns using the line text (`Document.text` when present, scip-java fills it; else the blob) and records when a document's encoding was assumed. scip-java corrects javac's tab expansion for leading tabs only; interior tabs can shift columns.
- `SymbolRole` bits: Definition 1, Import 2, WriteAccess 4, ReadAccess 8, Generated 16, Test 32, ForwardDefinition 64.
- Symbol grammar: `<scheme> <manager> <package-name> <version> <descriptor>+` with `.` for an empty field; descriptors `name/` (namespace), `name#` (type), `name.` (term), `name().` / `name(+1).` (method), `[T]`, `(p)`, `name:`, `name!`; locals are `local <id>` and are unique per document only. `scip::symbol::parse_symbol` parses them.
- `SymbolInformation.kind` (Class 7, Method 26, Function 17, Interface 21, …) is the kind source; `enclosing_symbol` is set for locals only, a global symbol's parent is its symbol minus the last descriptor. `Relationship.is_implementation` gives `IMPLEMENTS`; `is_reference` marks overrides for find-references. **The flag carries no direction:** scip-java 0.13.1 sets it on both sides of an override inside the workspace (on `java-spring-jpa`, `DefaultAuthService#authenticate().` and `AuthService#authenticate().` each list the other, and so do the two types), so the join takes the direction from the syntax's supertype declarations (amendment 16).
- A `docker run --rm` client killed by a signal leaves its container running: the daemon owns the container, so a budget overrun needs `docker kill <name>` on a named container (amendment 18).
- `Index.external_symbols` lists externally defined symbols and is never a definition in the workspace.

- Image: `eclipse-temurin:25` plus Maven 3.9.1, Gradle 9.4.1, coursier and JDKs 25/21/17; `WORKDIR /sources`; the `scip-java` wrapper picks a JVM through coursier (`JVM_VERSION`, default `21,17`). Java 17+ only; Scala and sbt were dropped in 0.13.

Detection looks in the working directory only: `pom.xml`, else `settings.gradle`/`gradlew`/`build.gradle(.kts)`. **It runs the full build**: Maven `clean verify -DskipTests` with a javac wrapper carrying the plugin; Gradle `clean scipPrintDependencies scipCompileAll` through an init script applied to all projects. ## Amendments (step 3b, 2026-10-01)

1. **Ownership of a file.** A file belongs to the deepest build root that contains it, among all jobs; it is exact when that root's index is `ok`, heuristic otherwise. A nested package whose own job failed therefore stays heuristic even when an outer index happens to carry its documents, and a project's join only sees the files it owns.
2. **`scip_status` detail is a function of the commit and the cache.** It records `indexer`, `status`, `image` (or `reason` for `skipped`/`unsupported`), `elapsed_ms` (the container run's time, the cached run's when served from the cache), `unpinned`, `coverage` when ok and `stderr_tail` when not. Whether the index was served from the cache is printed by `rb index`, never stored: invariant 5 needs a warm re-index to dump byte-identically. `rb status` prints these diagnostics as `scip:` lines.
3. **Statuses.** `RunStatus::Skipped(reason)` covers `--no-scip` and an unavailable Docker (`docker version` failing); `unsupported` (scip-java, no usable image) is never cached; `failed` and `timeout` are cached and served like `ok`, so a broken project is not rebuilt until its inputs change.
4. **Join targets.** An edge's target must be a symbol that matched a Tree-sitter definition, since only those have `Symbol` nodes. A matched reference to a symbol the index defines at a range Tree-sitter does not treat as a definition (a field, a constant) is counted as `references_unanchored`. Design §5.3's "every definition occurrence becomes a `Symbol` node" is not built: it would add a node per field and constant.
5. **`--no-scip` runs are a different tool configuration:** `tool_versions.scip` records it, so an index with indexers after one without is not "up to date".
6. **Bare names.** `rb callers findUserByEmail` lists both `findUserByEmail` methods of the fixture rather than picking one; the goldens use the `findUserByEmail().` form (S6 note).

## Amendments (step 3c, 2026-10-01)

7. **Annotation-anchored definitions (scip-java).** scip-java 0.13.1 anchors a member's definition occurrence at the first text match of the member's name from the top of the member, so `@PostMapping("/login") public String login(…)` gets its definition occurrence inside the annotation's string, not at the method name. The join's fallback (`rb_indexer::scip::definition_before_name`): when no global definition occurrence sits at a Tree-sitter definition's name, it accepts one whose symbol's last descriptor name equals the definition's name and whose span lies inside the definition's span, before its name (its modifiers and annotations); nothing outside those bounds is considered. Such matches are counted in `coverage.definitions_matched_by_name` (a subset of `definitions_matched`) and printed by `rb status` as `(n by name)`. Invariant 6 holds: the range is one the indexer emitted, inside the definition. Unit-tested on a synthetic index; on `java-spring-jpa` it recovers `AuthController#login().` (15/15 definitions, 1 by name).
8. **scip-java runs in the locally built image** `rb-scip-java:0.13.1` (`docker/scip-java`), not the 6.75 GB published one. A local image has no registry digest, so the cache key's image part is its image ID (`docker image inspect --format '{{.Id}}'`, resolved per job through `Runner::image_id` before the cache lookup, `rb_scip::resolve_image`); the containers run by that ID, and `scip_status.detail.image` reports it. When the image is absent the job is `unsupported` (never cached) with a reason pointing at the README; nothing builds it implicitly, and the Java e2e tests skip with a notice. Maven only: the fetch phase runs `mvn -B -q org.apache.maven.plugins:maven-dependency-plugin:3.11.0:go-offline` and then `mvn -B -q clean verify -DskipTests` online, with `<cache_dir>/m2` mounted at `/root/.m2`; the index phase runs `scip-java index --build-tool Maven -- --batch-mode --offline clean verify -DskipTests` under `--network none`. Verified 2026-10-01 on `java-spring-jpa` (fresh run 6.1 s on a warm `.m2`, cached 0.15 s; the fixture's dependencies had taken 80 s and 281 MB to fetch) and on the polyglot `services/auth`, whose pom gained `spring-boot-starter-web`, `spring-boot-starter-jdbc` and `spring-cloud-starter-openfeign` (via the `spring-cloud-dependencies` 2023.0.3 BOM) so that it compiles (+19 MB, 7 s). Maven logs to stdout, so the runs set `MAVEN_OPTS=-Dorg.slf4j.simpleLogger.logFile=System.err` to get its `[ERROR]` lines into the stderr tail. Exported files are never executable, so scip-java cannot prefer a repository's `./mvnw` (which downloads Maven) over the image's `mvn`. Gradle jobs stay `unsupported("scip-java Gradle builds are not verified yet")` (M6). The verified-facts note above about offline indexing being unverified for scip-java is superseded.
9. **Dispatch steps stay `dispatch`.** With exact edges, `rb callers DefaultAuthService.authenticate` lists `AuthController#login()` as `dispatch, via dispatch`: the walk caps a step through an overridden method at `Certainty::Dispatch` (CHA, M3a rule in `rb_store::code`), whatever the certainty of the edges; `rb impact AuthService#authenticate().` shows the underlying `CALLS` and `IMPLEMENTS` edges as `exact`.
## Amendments (step 4, 2026-10-01)

11. **Packages (S8, design §5.5) are read from occurrences, not from lockfiles.** In a SCIP-ok project, every occurrence of a global symbol the index does not define names a package through `scip::symbol::parse_symbol` (`rb_scip::package`): `Package { manager, name, version }`, node key `<manager>/<name>@<version>` (`@?` for an empty version), name attribute the package name. scip-java prefixes Maven artifacts with `maven/` (`maven/org.springframework/spring-web`), which the key drops, so it reads `maven/org.springframework/spring-web@6.1.13`; the JDK is a package too (`maven/jdk@21`). Skipped: local symbols, namespace-only symbols with no package (`scip-java maven . . org/springframework/`), and symbols of the project's own package that the index does not define (scip-typescript files the generated Prisma client under `node_modules/.prisma/…` with the project's own name and version). Occurrences are used whether or not Tree-sitter captured them (an import binding, an annotation), so the packages are not limited to `references_external`; symbol *relationships* are not used (`spring-data-commons`, reached only as a supertype of `JpaRepository`, is not a dependency of the Java fixture). Edge: `Service -DEPENDS_ON-> Package`, provenance `scip`, certainty `exact`, where the service is the referencing file's (`IN_SERVICE`); one evidence per service and package, the first site (lowest path, then span) among the service's files. Not built: `Symbol` stubs for external symbols and `REFERENCES`/`CALLS` edges into them (design §5.5); a node per external symbol would add thousands of nodes per project (petclinic: 1,220 external reference sites) for no question the graph answers yet, and amendment 4 already limits edge targets to symbols with nodes. `rb service <name>` prints the packages (`Packages (n)`, or `Packages: none`); `rb status` does not count them.
12. **Versions are the indexer's, not the lockfile's.** scip-typescript takes a package's version from the `package.json` it resolves the import through, so a subpath import can carry a version of its own (`libphonenumber-js/max@HEAD` next to `libphonenumber-js@1.11.1` in class-validator), a `@types/*` package stands in for the untyped runtime package it describes (`@types/validator`, never `validator`), and a dependency used only through untyped objects has no occurrence at all (`express` in the TypeScript fixture). scip-java reports the artifact version it compiled against. Resolving these against `package-lock.json`, `pnpm-lock.yaml` or Maven's dependency tree is out of scope for M3b.
13. **S11's TypeScript repo is class-validator, not hono.** hono (`18331a905e24`) is a pnpm workspace whose lock lists 1,085 packages, among them `workerd`, `esbuild`, `sharp`, `wrangler`, `vitest` and 14 `@cloudflare/*` packages; the root job would `pnpm install --frozen-lockfile` all of that under amd64 emulation (the fixture's 100-package install took 6.3 s; this one is well over 10 minutes and, with the native binaries, over 500 MB) on a host with 2.8 GiB free. `typestack/class-validator` at `2e1a5c27dbd6` (shallow clone in the scratchpad, 2026-02-26) was measured instead: one package root with `package-lock.json` (518 packages) and a root `tsconfig.json`, 138 TypeScript files under `src/`.

14. **Files without a document are counted (found in S11).** class-validator's `tsconfig.json` excludes `test/**`, `sample` and `**/*.spec.ts`, so scip-typescript emitted 136 documents for the 180 files with facts under the root: the other 42 (25 `sample/`, 13 `test/`, 2 `src/`, 2 root `.js`) are owned by a SCIP-ok root and therefore get no heuristic edges (invariant 1) and no exact ones either, and nothing counted them: 927 of the heuristic twin's 1,332 call sites were in those files. The join now reports `coverage.files_without_document` (owned files with facts for which the index has no document); `rb status` appends `, n files without a document` when n > 0 (the fixtures have 0, so their goldens are unchanged). Not changed: such files stay without edges. Indexing them heuristically would mix the two tiers inside one project (invariant 1), and telling a deliberate exclusion from an indexer gap needs the tsconfig's `include`/`exclude`, which is M6 work; the count makes the gap visible until then.

## Amendments (evaluator pass 1, 2026-10-01)

15. **Ownership is by document (D1).** Amendment 1 made every file under a SCIP-ok root exact, so a file the index has no document for (a Python script under a Maven root; a TypeScript file the tsconfig excludes) lost its heuristic edges and got no exact ones; amendment 14 only counted the loss. Now `assemble` marks as exact only the files in `Joined::documented` (the owned files the `ok` index has a document for); every other file keeps Tier B, whatever root it lies under, so invariant 1's unit is the file, not the project. The join takes each file's language, and `coverage.files_without_document` counts only files of the indexer's languages (`rb_indexer::scip::indexed_languages`: Java for scip-java; TypeScript, TSX and JavaScript for scip-typescript): a Python file under a Maven root was never scip-java's to cover and is not a gap. Unit: a Python file under a SCIP-ok Maven root keeps its heuristic `main → helper` call with the count at 0; a TypeScript file without a document keeps Tier B next to a documented one with the count at 1. e2e: `fixtures/java-spring-jpa/scripts/tool.py` (`main → helper`) carries a heuristic call next to the exact Java edges; the S7 sweep checks the documented `src/` files and the project's package; `scip-status.txt` reads `1 resolved` and the card `python 1`, with 0 files without a document.
16. **`IMPLEMENTS` runs in the direction the syntax declares (D2).** The join emitted an `IMPLEMENTS` edge for every `is_implementation` relationship of a matched symbol; scip-java sets the flag on both sides of an override, so `rb impact DefaultAuthService.authenticate` listed the interface method as a breaking dependant. Now `A IMPLEMENTS B` is emitted only when A's type holder (`scip::type_holder`: the definition itself when it is a type, else the nearest enclosing type of a method, function or constant) declares a supertype whose simple name is B's last type descriptor (`rb_scip::last_type_name`: `Dog` for `p/Dog#`, `Animal` for `p/Animal#sound().`; `scip::declares_supertype` compares simple names, so `a.b.Foo` and `Foo<T>` both name `Foo`). Unit: a symmetric index gives one edge per level (`Dog# → Animal#`, `Dog#sound(). → Animal#sound().`) and nothing back. e2e golden `scip-impact-default-authenticate.txt`: 0 breaks, 1 affected (`AuthController#login()`, `dispatch`, amendment 9).
17. **`tool_versions.scip` is `off`, `unavailable` or `on` (D3).** Amendment 5's boolean recorded an index without Docker as `scip: true`, so a heuristic snapshot indexed while Docker was down counted as "up to date" once Docker answered. `rb index` decides the `ScipMode` (`--no-scip` → `Off`; `docker version` failing → `Unavailable(reason)`; else `On`) before the up-to-date check and passes it to the indexer, which no longer probes Docker itself. e2e: the same repo indexed with `PATH=/usr/bin:/bin` for the child, then with `--no-scip`, then with Docker: a run is "up to date" only with its own mode.
18. **Named containers and `docker kill` on a budget overrun (D4).** Containers are named `rb-scip-<input_hash16>-<fetch|index>` (`ContainerRun::name`; the work directory's name plus the phase; sequential fetch runs reuse the name because `--rm` removes each before the next). Unit: a fake `docker` script whose `run` sleeps and whose `kill <name>` ends it, once with a container to kill and once without.
