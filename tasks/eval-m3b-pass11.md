## New findings

### N1: major. The enum-constant-body allowance pairs an anonymous class's method inside an enum constant, in its arguments or in its body's initializer, with a constant-body method only Tree-sitter sees.

**Cause.** In `definitions_unpaired` (`crates/rb-indexer/src/scip.rs:815`–`835`), rule (ii) accepts a Tree-sitter method anchored by a bound local when all three hold:
- the local's kind is `Method`;
- the innermost *other* definition range around its occurrence is an enum constant (kind `""` or `EnumMember`);
- the constant's type is the Tree-sitter parent's anchor.

Two other shapes pass the same test:
- an anonymous class's method inside a constant body's initializer block;
- an anonymous class's method inside the constant's arguments.

scip-java gives no definition occurrence or range to an anonymous class or an initializer block, so for both shapes the innermost range is the constant, exactly as for a genuine constant-body method. Amendment 75 tested `Enm2` (anonymous class inside a constant body's *method*: the method's range is innermost) and fields, but not these two.

**Repro.** Real image, `--no-cache --force`, project `t11esc` (UTF-8 pom, ASCII sources). `rb status`: `documents rejected 8 (structure_disagreement 8)`, `unmatched 0`, `definitions without occurrence 0`, `5 local definitions`. Each file has `syntax_error None`.

### N2: major. A supertype clause that only Tree-sitter sees reverses an override: false exact `IMPLEMENTS` from the superclass's method to the subclass's.

**Cause.**
- scip-java emits `is_implementation` on both sides of an override (amendment 16).
- The join keeps the side whose source type reaches the target type through **Tree-sitter's declared supertypes** (`reaches_supertype`, `scip.rs:546`–`550`). The supertype name resolves through the index's own occurrence inside the clause's span (`declared_supertypes`, `:1046`).
- No agreement check compares the supertype clauses. A type-parameter bound (`<T extends Sup2>`) that Tree-sitter reads as `extends Sup2` therefore resolves to the bound's `Sup2#` occurrence.
- The type parameter's own definition occurrence (`Sup1#[T]`, descriptor `[T]`, range `[2,0,4,1]`) sits in Tree-sitter's comment. It is neither `).` nor `#`, so rule (a) and `definition_disagreement` pass over it.

**Repro.** Same project and run. `Sup1.java`:

```
package p;

class Sup1 /* */ <T /* */ extends Sup2 /* */ > /* */ {
  void n() {}
}

class Sup2 extends Sup1<Sup2> {
  void n() {}
}
```

- javac reads `class Sup1<T extends Sup2>`.
- Tree-sitter reads `class Sup1 extends Sup2` with no syntax error.
- scip-java: `Sup1#n().` `is_implementation` → `Sup2#n().` (the reverse twin), `Sup2#n().` → `Sup1#n().`, and `Sup2#` → `Sup1#`. `Sup1#` has **no** relationship to `Sup2#`.
- Accepted with these exact edges:
  - **`p/Sup1#n(). IMPLEMENTS p/Sup2#n()`** at `[3,7]`: false, since `Sup1` is the superclass;
  - `p/Sup2#n(). IMPLEMENTS p/Sup1#n()` (true);
  - `p/Sup2# IMPLEMENTS p/Sup1#` (true);
  - `p/Sup1# REFERENCES p/Sup2#` (true: the bound names `Sup2`).
- `rb impact` on `Sup2#n()` would list `Sup1#n()` as an exact implementer. `bf43351` emits the same edges.

**Why major.** It is a false exact edge in a direction amendments 16/26/43 claim the syntax decides. It falls in no line of amendment 71's covered list or its uncovered list, which mentions only references that change callee, encodings, TypeScript and Gradle.

**Suggested fix (calibrated here at 0 cost).** Accept a declared supertype only when the source type's own `SymbolInformation` has a relationship to the resolved symbol (scip-java relates every type to its supertypes). Equivalently, reject a Java document where one is missing.
- Measured with the probe (the join's resolution rule over every Java document): all declared supertypes confirmed on petclinic (17/17), jsoup (168/168), vavr (331/331) and TheAlgorithms (159/159). On `t11esc`, 1 of 2 is unconfirmed, and it is `Sup1 → Sup2`.
- The recommended escape rule of N1 would also reject `Sup1.java`.

**Regression test.** The measured `Sup1.java` occurrences and relationships above (type parameter `Sup1#[T]` `[2,23]`, bound `Sup2#` `[2,39,2,43]`). Expect no `Sup1#n() IMPLEMENTS Sup2#n()`, and either the document rejected or the clause unresolved.
