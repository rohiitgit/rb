## New findings

### G1 — major — the supertype resolution of amendment 26 picks a type *argument* when it is a nested type of the raw type: one false exact `IMPLEMENTS` edge and three silently lost ones (invariant 2, S5)
- Repro (scratch Maven project `j4`, 19 files, no dependencies, real `rb-scip-java:0.13.1`; `b/Marker.java`: `public interface Marker<T> { class Disc implements Face { public double area() { return 1; } } }`; `b/Face.java`: `public interface Face extends Marker<Marker.Disc> { double area(); }`; `b/Use.java` calls `f.area()` on a `Face`).
- Observed: dump has `b/Face#area(). IMPLEMENTS b/Marker#Disc#area(). scip 5` and no `b/Face# IMPLEMENTS b/Marker#`; `rb impact 'b/Marker#Disc#area().'` prints `breaks (1): b/Face#area()  exact`, the interface as a dependant of its implementation (pass 3's F2 symptom, same `impl=true` on both sides). Expected: `Face# → Marker#`, `Marker#Disc# → Face#`, `Marker#Disc#area() → Face#area()` only.
- Cause: the index's occurrences inside the clause `Marker<Marker.Disc>` are `b/Marker#` [3,30..36], `b/Marker#` [3,37..43], `b/Marker#Disc#` [3,44..48] (decoded from the cached index). `declared_supertypes` (`crates/rb-indexer/src/scip.rs:394-425`) replaces the earliest symbol by any later one in the span that `starts_with` it, so the type argument `Marker.Disc` wins over the raw type `Marker`. The walk then reaches the target (`Marker#Disc#`) in one step and accepts the reverse link. The same rule loses true edges without a count: `a/Cfg.java`: `class Cfg extends Base<Base.Options>` (occurrences `a/Base#`, `a/Base#`, `a/Base#Options#`) → resolved `Base#Options#`; the index's `Cfg# → Base#` and `Cfg#run(). → Base#run().` relationships produce no edge and `supertypes_unresolved` stays 0. `Face# → Marker#` is lost the same way.
- Expected rule: resolve only the *name* part of the clause item. `rb_syntax` already separates it (`generic_type`'s first named child; TS `extends_clause.value` without `type_arguments`): make `Supertype.span` cover the name only, or accept a longer symbol only when its occurrence starts where the previous one ends plus one `.` (a qualifier chain), never after `<`.
- Regression test: the `Face`/`Marker.Disc` and `Cfg`/`Base.Options` files in `scip::tests` with the three-occurrence layout above (both directions listed), asserting the forward edges only and `supertypes_unresolved 0`; an `rb-syntax` test that a generic supertype's span excludes its arguments.

### G2 — major — an `environment` or `timeout` outcome produces a heuristic snapshot that is "up to date" for every later plain run (amendments 30/31 are not met without `--force`)
- Repro: `PATH=<shim exit 125>:$PATH rb index t4 --repo x --force --no-cache` → `scip: . scip-typescript environment …: shim: docker run refused`, then with the real `docker`: `rb index t4 --repo x` → `x: up to date — live snapshot 492 already covers 94e1075d6a1d`. - Expected: a snapshot with any `environment` or `timeout` job is never "up to date" (record an `incomplete` flag in `tool_versions` or the snapshot's coverage and check it next to `tool_versions`), or the check re-runs those jobs.
